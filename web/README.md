# موقع وِرد — المصدر

المستودع هو مصدر الموقع. النشر (`web-deploy/deploy.mjs`) يبني الملفات من هنا ويرفعها على Cloudflare؛ لا يوجد أي تعديل على الموقع المنشور خارج هذا الفولدر.

## البنية
- `site/` — كل ملفات الموقع كما تُخدَم (صفحات، بيانات، خطوط، صور مخزنة نصًا base64 كما في الـ Worker).
- `ui/` — أجزاء `ui.js` بالترتيب المكتوب في `manifest.json`:
  - `00b-dom.js` أول حاجة: المراقب المشترك `__wOnDom` و`__wWait` (استنّى عنصر يظهر بدل التكرار بمؤقت).
  - `core/NN-name.js` كود التطبيق الأساسي متقسّم حسب الميزة (الأذكار، المصحف، المواقيت، الأذان، الإعدادات، الأدوات، الأطفال…).
  - بعدها الوحدات (`NN-name.js`)، كل واحدة تبدأ بعلامة `/*name*/`.
- مصادر موحّدة في `site/app.js` (لازم تتستخدم بدل أي نسخة محلية): `__ar`/`__en` للأرقام (تحترم إعداد «123»)،
  `__nowH` ساعة المدينة المختارة، `__t12` صيغة ١٢ ساعة، `__nextPrayer()` الصلاة القادمة.
- ألوان الأسطح الغامقة: `--hero-a`/`--hero-b` للخلفية و`--on-hero-acc` للنص المميّز فوقها، متعرّفة للمظهرين.
- `css/` — أجزاء `styles.css` بنفس الفكرة.
- `manifest.json` — قائمة الملفات ونوع كل ملف وترتيب الأجزاء.
- `build.mjs` — يجمع الملفات بالشكل اللي الـ Worker محتاجه.

## النشر
GitHub Actions ← «Deploy website (manual)» ← Run workflow.
- يقارن الناتج بالمنشور ويكتب الملفات اللي اتغيّرت؛ لو مفيش تغيير ما بيرفعش حاجة.
- يزوّد إصدار الكاش في `sw.js` تلقائيًا عند أي تغيير.
- `dry = yes`: بناء ومقارنة بدون نشر.
- بعد كل نشر: روبوت الفحص (`qa/qa.mjs`) يشتغل لوحده، والصور في فرع `qa-shots`.

## الخطة
أي تعديل جديد يتحط في جزء `core/` الخاص بالميزة أو في وحدتها، مش في ملف جديد فوق القديم. ممنوع مؤقتات إعادة المحاولة، وممنوع إصلاح ألوان بعد الرسم: الحل في الـCSS.
